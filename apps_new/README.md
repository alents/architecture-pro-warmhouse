# Smart Home Sensor Management API ver2

В данной версии приложения мы выделяем из монолита `smarthome-app` два микросервиса telemetry-collector и sensor-poller и
расширяем функционал монолита, добавив возможность возврата телеметрии для датчика температуры (реализация запроса 
`GET /api/v1/sensors/:id`).

Микросервис `sensor-poller` с заданной периодичностью запрашивает зарегистрированные в системе датчики температуры через
`temperature-api` и отправляет событие sensorChanged в брокер RabbitMQ. На данное событие подписан микросервис `telemetry-collector`, 
который сохраняет полученное из события значение температуры и время изменения значения в базу данных.

Монолит `smarthome-app` при обработке запроса получения данных сенсора `GET /api/v1/sensors/:id` делает запрос к микросервису
`telemetry-collector` `GET api/v1/telemetry/:id` на получение значений датчика за последние сутки и возвращает их дополнительно к существующей
информации.

Микросервис `sensor-poller` реализован на Kotlin   
Микросервис `telemetry-collector` реализован на Python

## Запуск сервиса

```bash
docker-compose -d --build
```

### Тестирование
Для тестирования можно использовать коллекцию Postman `smarthome-api.postman_collection.json`
В скрипт инициализации базы данных добавлено несколько датчиков для тестирования с идентификаторами 1,2,3

### URL
http://localhost:8080

### Эндпоинты для тестирования
`GET /api/v1/sensors/:id` - возвращает атрибуты сенсора + его телеметрию за текущие сутки
